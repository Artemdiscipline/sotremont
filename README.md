# СотРемонт

Работающий локальный сайт сервисного центра в Казани. React 19, TypeScript strict, Vite; две runtime-зависимости — React и React DOM. Без серверной формы, корзины, трекеров и внешних шрифтов.

## Запуск

Зависимости уже установлены. Одна команда:

```powershell
npm run dev
```

Откройте адрес, который напечатает Vite; обычно http://127.0.0.1:5173/.

На новой машине сначала выполните `npm ci`. Нужен Node.js 22.12+ или более новая поддерживаемая версия.

```powershell
npm run check   # строгая проверка TypeScript
npm run build   # production-файлы в dist
npm run preview # локальный просмотр собранной версии
```

## Как работает заявка

Форма ничего не отправляет на сервер и не хранит данные после перезагрузки. WhatsApp открывается с URL-encoded текстом. Кнопка Telegram сначала запрашивает копирование, резервирует вкладку, а после успеха открывает чат. При отказе Clipboard API текст выделяется, выводится понятное сообщение и отдельная ссылка. Если браузер блокирует вкладку, доступен тот же ручной переход. Реальное сообщение отправляет сам пользователь. Кнопки аксессуаров открывают запрос наличия и возможности бронирования; бронирование не изображается завершённым.

## Что заполнить перед публикацией

Все поля находятся в `src/data/site.ts`; ищите `TODO: подтвердить у владельца`.

1. `seo.canonicalUrl`: HTTPS-адрес нового сайта с завершающим `/`. Сейчас `null`, потому что домен не предоставлен. До его заполнения есть `noindex`, robots.txt запрещает индексацию, sitemap.xml содержит корректный пустой urlset. После заполнения и пересборки автоматически появятся canonical, og:url, абсолютный og:image, заполненный sitemap и разрешение индексации. Не подставляйте домен старого сайта.
2. Прайс: уточнить, входят ли детали в суммы; стоимость диагностики, защитного стекла и заднего стекла. Опубликованные стартовые цены взяты из 2ГИС, дата/источник показаны рядом. Замена задней крышки и заднего стекла не приравниваются без подтверждения. Сроки остаются `null`.
3. Гарантия, согласование цены до начала работ, возврат деталей, ремонт при клиенте, правила записи, бронирования и праздничный график.
4. Возможность ремонта планшетов, часов и конкретных моделей компьютеров. Для неподтверждённых моделей сайт формирует вопрос, а не обещание.
5. Имена, роли, специализации и опыт мастеров; фотографии команды, входа и до/после с правом публикации. Структуры и компоненты готовы; пустые поля не публикуются.
6. Актуальность рейтингов, отзывов, ассортимента и наличия. Даты проверки и ссылки сохранены в конфигурации и журнале источников.
7. Реквизиты и окончательная редакция политики под фактический хостинг и бизнес-процесс. При появлении backend-формы потребуется отдельная реализация согласия, хранения и удаления данных.
8. `seo.metrikaId`: оставлен `null`. Аналитика не подключена. Поле — место для будущей интеграции; один ввод номера не запускает отслеживание. При подключении согласуйте правила данных и обновите политику.

## Размещение

`dist/` можно отдавать любым статическим HTTPS-хостингом. Backend, API-ключи и платные карты не нужны. Robots и sitemap генерируются из той же конфигурации; вручную дублировать данные в `public/` не требуется. Внешние карты открываются по прямым ссылкам, поэтому на сайте нет незагружаемого iframe.

## Браузерная проверка

В `output/playwright/check-flows.js` и `check-layout.js` сохранены проверки для Playwright CLI. Сервер должен быть запущен на 5173.

```powershell
npx --yes --package @playwright/cli playwright-cli open http://127.0.0.1:5173/
npx --yes --package @playwright/cli playwright-cli run-code --filename output/playwright/check-flows.js
npx --yes --package @playwright/cli playwright-cli run-code --filename output/playwright/check-layout.js
```

В тесте перехода Telegram внешний ответ подменён локальной заглушкой: проверяется адрес вкладки и Clipboard, никакие сообщения не отправляются.
